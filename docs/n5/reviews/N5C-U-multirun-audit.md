# N5C U：多 run 专项审计（Gate A）

依据项目外 `N5C_U_Refinement_Audit_Codex_Taskbook.md` 及用户随后确认。
从 PR #100 head `f5a479ae36c15e356cddd063235b33318856a86e` 建立
`feature/n5c-u-refinement`；PR #100 保持 open，旧七组结果只读。

## 运行前固定的范围

- 只跑 Deferred、busy=relocate 的 FA-FFP/full/noU；seed=1，run=11–15。
  run 11 复用验证后的原始三组，新增 run 12–15 共十二组，每组 800 任务、1300 s。
- 不改变 R/M/U、min-max、tie-break、START/Frequency、Recovery、Fault、Routing、输入或 deadline。
  只为正式运行入口增加显式 random-run，旧默认仍为 11。
- 不设置 T 阈值、5% 容差或自动升 Gate B 的规则。先报告各 run 的全部指标和配对差异，
  待共同审阅后决定是否研究 recent-U；当前 FULL 和 NO_U 定义保持不变。
- 相同故障条件指相同模型/参数/随机流分配和同 run，而非强制最终故障 JSON 一样。
  在线 generate 的时序反馈如造成差异，应输出并解释，不能切换 replay 消除差异。
- 实际 full/noU 的选点差异与同一 full 候选快照中去掉 U 的反事实排名分别统计。
  START 缺失、时刻变化和未成功准入不混成“U 直接改变选点”。
- busy 分母逐组取故障时具有 designated backup 的事件；catch 输出样本数与未追平数，
  全样本与同任务/同故障时刻/同类型的配对样本分开，未追平不记为 0。
- WU 与 eq-WU 分列；历史统计只用决策时刻以前的实际执行区间，不把预留等待计作 busy。
  task 140 仅作诊断样例，recent-U 尚未实现，其值和胜者标 N/A。

## 结论：NO_MODEL_CHANGE

**Gate A 审计通过，但不支持从 run 11 推广出“noU 稳定优于 full”。建议保留 V4 FULL，
停止本轮模型修改；是否继续研究 recent-U 留待共同审阅，不自动进入 Gate B。**

noU 在 run 11–13 各多完成 1 个任务，在 run 14、15 分别少完成 2、1 个。
五轮 full/noU 都完成 **3993/4000** 个任务-运行实例，busy 都为 **5/409**。
noU 的合计总容量等价浪费低 0.79%，但 405 个共同追平样本平均慢 **6.485 ms**，
额外应用发送量多 **3.087279 GB**。结果是取舍，不是稳定支配关系；没有使用 5% 或其他容差裁决。
五个固定 run 只作描述性诊断，不宣称统计显著性，也不替代对 LRL/FA-LRL 的公平强基线比较。

actual execution waste 是实际执行浪费；active eq cost = actual execution waste + 常态保护等价成本；

链路利用率是五轮各自全网均值的平均。assignment HHI 的五轮均值为

## U 因果诊断与边界

- full 的 1991 次 committed START 中，选中候选的 dominant dimension 为 U=202、M=1789、R=0。
  但在同一候选快照只去掉 U 时，有 **1162 次**会换 remote：选中者由 M 主导，不等于 U 没有排除其他候选。
- 其中 **1091 次**，替代候选累计 U 更高，但此前已经连续空闲至少一个“当前任务剩余纯计算时间”。
  这是旧历史仍影响排名的诊断证据，不是“这 1091 次都该换星”的标签，也没有加入手调时间阈值。
- 两条真实 full/noU 轨迹有 **1169 次**共同 committed 任务选点不同，不能和上述反事实计数混为一谈。
  run 13/task 709 的 START 时刻不同；run 14/task 1 只有 full committed，两边任务均完成。
  `full-vs-noU-task-diff.csv` 保留全部 4000 个任务-运行对，`u-decision-audit.csv` 含 3981 个选中快照。
- task 140/run 11：13 号星累计 U=0.05517065，已空闲 12.133454 s；15 号星累计 U=0。
  当前任务剩余 5.507220 s，传播分别为 1/3 ms，R/M 相同；full 选 15，实际 noU 与同快照 noU 选 13。
  每轮独立输出 `run-*/task140-u-diagnostic.json`；未实现的 recent-U 值及胜者保持 N/A。
  合成单测验证“历史忙、最近空闲”与“历史从未忙”具有不同累计 U、相同零最近窗口忙时，
  不断言未来 recent-U 一定选某个节点。
- 真实故障事件在 run 11/12/14/15 三组相同；run 13 的 full 在 21 号星 965 s 多一次 F1。
  full 将 task 191 的恢复放在 21 号星（952.807682346 s 开始，实际计算 14.47309 s），noU 放在 12 号星。
  不同恢复负载改变温度，模型仍继续生成故障；既有 recovery immunity 保证该 attempt 不因 F1 再次中断。
  此次多出的事件不产生额外 primary recovery，三组仍各有 80 次恢复尝试。
  同一模型/RNG 配置不等于必须有相同 realized fault JSON；没有切换 replay。
