### Task 140 与长尾贡献

实际 FULL/noU/Rational-U 分别选择 remote **15/13/24**。Rational-U 不是 B0 快照的 23：
此前任务 262 的实际恢复从 FULL 的 24 转到 Rational-U 的 23，执行 4.020760 s，改变了节点历史。
在实际 Rational-U 的 task 140 快照中，23 的 U_global=0.012824485、U_rat=0.000864121，大于 M=0.0001377493；
24 从未忙过，U=0、传播 2 ms，比同分的 15（3 ms）更优，故选 24。
**在这个新快照中，累计评分也会选 24**：实际收益包含此前选点对整条轨迹的影响，不能声称只是本次衰减直接挽救任务。

FULL 的 REMOTE_REDO：catch 2779.013312 ms，最终超时；Rational-U 的 TAIL：catch 350.163312 ms，最终成功。
task 140 的实际执行浪费从 685,822 降到 4,900 WU（−680,922），不是减免实际发送或忽略恢复工作。

- 对 FULL 的总收益主要由 task 140 主导。去掉它，82 次配对 catch 平均 **慢 0.417 ms**（差值 P50=0），
  总等效浪费 **多 3,686.357 eq-WU**，实际执行浪费相同。另有 task 592 变快 263.237 ms，task 192/212 变慢 191.940/84.515 ms。
- 对 noU 的小幅收益主要来自 task 592：catch 快 261.135 ms、预留等待少 26,113.502 eq-WU。
  去掉 task 592，配对 catch 平均 **慢 1.024 ms**，总等效浪费 **多 8,846.198 eq-WU**；task 187 多执行 6,800 WU。

## 判断与停点

有继续验证的正向信号：保留了非零历史和 FULL 级别的分散性，run 11 完成率达到 noU，且未增大相对 FULL 的 busy 数。
但恢复/浪费收益明显受少数长尾影响，不能从一个 run 宣称普遍优于 FULL/noU。
**建议共同审阅后再决定是否补 run 12–15；当前没有必要测指数式。默认继续 FULL，不自动推广 Rational-U。**
这回答了历史惯性修正、noU 一致率、U 的实际作用、热点、task 140、长尾主导、是否补多 run 及是否需要指数式八项问题。
