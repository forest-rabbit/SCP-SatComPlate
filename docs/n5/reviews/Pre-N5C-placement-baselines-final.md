# Pre-N5C：四种 placement 的可行性消融

本轮把“筛选候选”与“候选排序”分开，保留最新历史行为为 **FA-FFP / FA-LRL**，
增加 minimal FFP / LRL；不实现 N5C，不改 checkpoint 故障后的恢复节点排序。
正式执行版本为 `b51cc9d638c2630068b5174bacfcaf1500d7d7e5`，分支 `feature/n5-baselines`。

## 定义与验证边界

| placement | 候选条件 | 排序 | 首选实际准入失败 |
|---|---|---|---|
| FFP (`ffp`) | healthy、idle、非 primary；pair 另要求 local 一跳、两节点不同 | 稳定 ID，pair 为 local-first | 当前决策停止，不尝试下一候选 |
| LRL (`lrl`) | 与 FFP 完全同集 | 当前 activeBackup + activeRecovery，稳定 ID 消歧；pair 仍 local-first | 同上 |
| FA-FFP (`fa-ffp`) | 保留对应操作原有可行性筛选 | FFP 排序 | 保留原操作的筛选/尝试规则 |
| FA-LRL (`fa-lrl`) | 与 FA-FFP 完全同集 | LRL 排序 | 同上 |

默认 `fa-ffp`。FA 不是新增一套统一的强准入：Fixed 保留原三路径筛选及真实运行准入，
不添加 CompFRR 的频率、storage/deadline 候选搜索；CompFRR 保留原有有序硬约束搜索。
R0/R1 保留其 INPUT、RESULT 可达性和 compute deadline 检查。minimal 只把这些检查移到
选定候选之后，不绕过真实 NetworkTransferEngine、计算预留、备份池或 deadline。
同一 minimal 决策不继续搜索；已有后续故障检查点/真实容量释放事件仍可重新决策，
1+1 则仍为首次 TASK_RUNNING 的一次性申请。

四种 placement 作用于 Fixed/CompFRR 的故障前 pair，以及 R0/R1 的原生 single-node 角色。
checkpoint 故障后的恢复/迁移继续使用冻结的候选框架与稳定 ID 排序。
R0 的 accepted recovery 计入实时负载；R1 的真实副本 assignment 和 takeover recovery
分别记账、按真实生命周期释放。LRL 不读取累计分配次数或未来队列。

新增 `placement-selections.csv` 记录选中的 pair/node 和同步准入结果；ACCEPTED 不代表
异步 INPUT 或初始化已成功，须与 transfer/protection/recovery 账本联查。
minimal 的旧全候选 path/hard-prefix 统计留空，不把未检查候选伪装成可行。
详细合同见 [protection README](../../../contrib/satcompute/protection/README.md)。

本地构建、23 个 C++ 测试程序、118 项 Python unit（117 通过、1 项原生切片依赖条件跳过）、
全部维护 smoke/regression 通过。新测试覆盖 512 种候选属性组合、同集/稳定排序、
真实容量拒绝后 minimal 停止而 FA 可选替代、R0/R1 首选 deadline 不足、16 组小场景、
真实容量释放重评与最终负载归零。原 N4B 联合回归仍为 88 完成/12 失败、483 条概率匹配。
没有运行 GitHub CI。

正式 rename 门禁：R5 / R7 分别比对 31 / 32 个既有 CSV、JSON 文件，
其中 CSV 498215 / 496747 行；仅允许 placement 名称、输出路径、执行身份与墙钟改变。
两组唯一新增文件均为 `placement-selections.csv`。R5 仍 800/0，
waste=1666239.5239 eq-WU、额外网络=197947085680 B；R7 仍 799/1（574），
waste=4295717.8292 eq-WU、额外网络=105397736792 B。

## 正式矩阵与统一口径

66 星/66 计算星、800 个任务、1300 s；每星 100000 WU/s、10 Gbps、fixed 1 ms、
20 s 网络切片、deadline factor=1.3、10 GB/节点备份池、seed1/run11、online generate。
F1/F2/F3 模型、独立抽样、路径/ECMP、cost tiers、任务与生成器不改。
总 WU=352513119，LLM WU=61333200；400 WU/token，153333 token，
KV=17585455104 B；INPUT=194119753287 B，RESULT=100166291859 B。
R5-FA-FFP 和 R7-FA-FFP 先作历史等价门禁，计入 32 组，不额外重复运行。

R0=Full Recompute；R1=真实 1+1；R2/R3=Fixed；R4/R5=CompFRR eager；
R6/R7=CompFRR deferred。R2/R4/R6 busy 时重算，R3/R5/R7 busy 时迁移。
R1 的 recovery attempted/accepted/success 分别表示主 attempt 故障、真实 takeover 和
故障后副本获胜；一次性副本 requested/admitted 单独统计。direct victims 包含被中断的
primary 或普通 replica 所属任务，不应与 takeover 次数混为一谈。

统一实际浪费：所有物理 attempt 真正执行的 WU，减去按 compute deadline 成功的每个逻辑任务
一份有效 W，再加正常保护 eq-WU 与真实 reserved-idle eq-WU。失败任务的已执行量全部是浪费；
planned 不补 actual，catchup/post-catchup 另列且不重复相加。RESULT 沿用 compute deadline 合同。

网络是实际源端应用载荷，十进制 GB，不是 hop-byte 或线速字节。normal/fault 按容错操作类型
划分，不是简单按墙钟故障时刻切开。1+1 计入真实 replica INPUT 和所有 losing RESULT，
只扣唯一 winner 的业务 RESULT；takeover 不新建传输，相关流量属于副本操作。
链路利用率另从每条有向链路实际序列化 busy 时间统计，报告全程平均及单链路最高全程平均。
R0/R1 的 checkpoint pair 和备份池为 N/A，不把未量化的 active working set 当成零存储优势。

   按 OFF frequency 触发类型与顺序逐条核对，容量事件均无新增抽样；不能仅按 task/time 去重。
   本轮只修正离线审计，不修改运行时去重/重试。
