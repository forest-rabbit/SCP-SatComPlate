## 实现边界与验证

- OFF→START复用canonical predictor的逐检查点联合q，按survival计算首次故障质量。
  初始化前的质量不计保护收益，但仍减少后续survival；得到P_ready和风险加权未来进度。
- Eager/deferred采用同一个未来计算价值；deferred的共同故障INPUT成本从两边评分同时消去，
  仍保留真实INPUT传输及deadline硬约束。正常保护项不按存活概率打折。
- ON仍用当前q和原检查间隔；不增加新决策模式、独立预测器或随机抽样。
  代表性进度只作评分，不写入真实checkpoint、故障进度、恢复startWork或actual WU。
- 配置与公式见[保护README](../../../contrib/satcompute/protection/README.md)、
  [生成器README](../../../contrib/satcompute/tools/generation/README.md)；不复制新配置层或SHA-256。
- 构建、107项Python测试（无跳过）、23个C++程序、11组smoke、4组maintained regression通过。
  原生位置切片下重复生成一致；受控用例覆盖早/晚/均匀风险、全部风险在ready前、
  整数token、同纳秒故障、真实恢复与INPUT/state先后依赖。按增量先小测，再运行完整场景。
- 正式执行提交：`f0f80e02fbbb04c009853cadb899c220a007ceed`，四组启动时工作区均干净。
  R4/R5/R6/R7壁钟分别1397.012/1383.692/1225.765/1232.025 s，退出码均0；
  最后链路窗口均1299–1300 s，800个唯一终态，资源/存储/网络预约无泄漏。
- 离线逐行重算 **15616条有可行候选的评分**（3857/3857/3951/3951），验证ON未改变；
  P_ready守恒容差1e-12，仅容纳浮点舍入。ready估计向上取整到ns，不能与真实commit混为一谈。
  后续仅修正离线审计对不足1 ns取整差值的检查，未改正式运行代码、未重跑或改写数据。
- 真实执行WU、成功有效工作、FlowMonitor与源端实际字节、deferred一次INPUT/一次tail合并均通过核对。
  正常运行不额外开启概率审计CSV；CompFRR的frequency CSV按合同输出新增评分字段。

### 对照结论

- R4→R6：额外网络减46.95%，正常期减59.13%；完成数相同，但实际浪费增63.26%，失败task集合不同。
- R5→R7：额外网络减46.78%，正常期减59.02%；完成数少1，实际浪费增127.80%。
- R4→R5：忙时迁移多完成2个，实际浪费减40.71%，额外网络减0.286%。
- R6→R7：忙时迁移多完成1个，实际浪费减17.27%，额外网络增加40974382 B（0.0394%）。

因此deferred的正常网络节省与故障期INPUT等待是实质取舍，不能宣称全面优于eager。
新旧轮同时改变START模型和LLM状态尺度，旧结果仅作背景，不把变化归因于单一因素。
