# N5C Rational-U：五轮三方审计

这是旧恢复合同下的五轮证据。后续仅补跑了[修正后的三组 run11](Recovery-direct-deadline-feasibility.md)；
其余受影响 run 未补跑，因此本页不是新恢复合同下的五轮结论。

结论：**本次证据不支持用 Rational-U 替换累计 U（FULL）**。三组均完成 3993/4000，
Rational-U 的 busy、配对恢复时延、总等效浪费均未优于 FULL；正向结果主要是 storage 分散性。
保留默认 FULL、PR #100 未合并及 #101 Draft；本轮停止，不测指数式、不调参、不运行 CI/合并。
五个固定 run 是描述性证据，不宣称统计显著性，也不预设其他场景的胜负。

  `625fff908104f4ba14443ed47ee856ec49d40adf`；复用原正式等价门禁和 425 文件 fixture 证据。

## 五轮合并结果

catch 主表使用**三方都有实际追平记录的相同 405 个事件**。每组实际 catch 各 406 个、未追平各 3 个；
三方共同样本排除 4 个缺少至少一方 catch 的事件，未追平不记为 0。完成/失败统计始终覆盖全体 4000 个任务实例。
Direct/Relocate/Recompute 是选择的恢复操作，失败可与操作分类重叠；各组 7 次恢复失败均为 compute deadline 超时。

总等效浪费 = 实际执行浪费 + 常态保护等效成本 + 预留空闲机会成本；后两者不能冒称实际 CPU 执行。
网络按去重后的实际发送 Byte 记账，含部分发送/取消，GB 为十进制；同星 LocalDelivery 不计网络发送。
完成总数相同不代表失败任务身份相同，因此业务字节略少不能独立解释成保护效率提高。
HHI 是各轮独立指标的均值，不把五轮分配合成一条轨迹；更低表示更分散。

相对 FULL，Rational-U 配对 catch **慢 14.303 ms（4.15%）**，总等效浪费 **多 0.664%**，
额外应用字节 **多 0.198%**；相对 noU，两方全部 406 个配对 catch **慢 7.800 ms（2.22%）**，
总等效浪费 **多 1.466%**，额外应用字节 **少 0.384%**。busy 都多 3 次（小样本下为 5→8）。
Rational-U 的 assignment HHI 接近 FULL、比 noU 低 40.34%；storage HHI 比 FULL/noU 低 7.01%/2.09%，
这是真实取舍，但尚未转化为更好的完成数、恢复时间或总成本。

## 单任务长尾排除审计

运行前固定：按每轮及五轮合并，分别找 catch/总浪费的**最大收益贡献**和**最大绝对贡献**；
贡献是 reference−Rational，绝对最大可能是 Rational 的损失。平局按 run、数值 task ID 升序。
两侧对称去除同一个 `(run,task)` 实例，不从五轮都删掉同 ID，也不重新仿真。
以下 Δ 都为 Rational−reference；时间负值更快、浪费负值更低。HHI/链路 exposure 不伪造排除后的新轨迹。
